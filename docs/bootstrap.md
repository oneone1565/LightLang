# 自举（bootstrap）方案与当前进度

目标：用 LightLang 写的编译器编译 LightLang 源码，逐级自举，最终由 Light 写的编译器
（`nlightc` 与 `nlightGo`）替代 Rust 版本。

## 阶段约定

```
stage0 = Rust 写的 nlightc              （当前可信实现）
stage1 = stage0 编译 bootstrap/lc.light
stage2 = stage1 编译 bootstrap/lc.light
stage3 = stage2 编译 bootstrap/lc.light
自举成立的条件：stage2 与 stage3 完全一致（逐字节比较 .ll）
```

计划中的脚本：`scripts/bootstrap.sh`，负责 stage1/2/3 的构建、比较与报告。

## 代码生成策略（自举编译器用）

- 所有值都是 i64；指针即 i64（Light 的 ABI）。
- 局部变量在进入块时 `alloca`，读写走内存，因此循环里不需要 phi 节点。
- 列表元素的类型在编译期不可知，读取时带上**运行期标签**（见下），由运行时分派。
- 不做内存回收：编译器进程短命，泄漏可接受。
- 只支持下面这个子集；`bootstrap/lc.light` 自身也只用这个子集。

## 子集（自举编译器支持的语言特性）

- 变量：`名字 = 表达式`（重新赋值）、`让 名字 = 表达式`
- 容器：列表字面量、`追加`、`弹出`、`长度`、`元素`、`元素文本`、`元素标签`、`包含`、`存在`、`键列表`
- 字符串：`+` 拼接、`==`/`!=`（按内容比较）、`.切片(i, j)`、`分割`、`去空白`、`字符`、`字符串`
- 控制流：`如果/否则如果/否则`、`当`、`对于`（改用索引循环）、`跳出`、`继续`
- 函数：`函数 名(参数: 类型) -> 类型:`、`返回`、递归
- 内建：`打印`、`读入`（读标准输入全部内容）

**不用**：元组解构、字典字面量、多文件、模块、异常、浮点（词法阶段会识别浮点字面量）。

## 语义规则（写自举编译器时必须遵守，否则会重复释放）

1. `元素(列表, 下标)` 返回**借用**指针（类型按整数处理，不会被自动释放）。
   把它交给「拥有型」参数（`行: 字符串`）会导致该值被释放两次，堆损坏。
   要取副本请用 `元素文本(列表, 下标)`（总是返回新字符串）。
2. 变量之间赋值是**所有权转移**：`乙 = 甲` 之后甲不再被释放。
3. `追加(列表, 变量)`、把变量放进列表字面量，也是所有权转移。
4. 返回参数或局部变量同样是所有权转移（调用方负责释放）。
5. 列表元素**不要**直接当容器传给函数：函数会释放它的参数。改成传
   `(容器, 下标)`，在函数内部用 `容器[下标]` 取用。
6. 字符串拼接不会释放「类型未知」的一侧（那是容器里的借用值）。

## 已加入语言的能力（为自举铺路）

| 能力 | 说明 |
| --- | --- |
| `且` / `或` 短路求值 | 守卫条件 `j < 长度(行) 且 行[j] == 33` 才安全 |
| 运行期标签值 | 列表下标读返回「值 + 标签」，`light_tagged/untag/tag_of` |
| 动态下标 | 容器种类未知时 `light_dynamic_get` 按标签分派（列表/字典/字符串） |
| 动态内建 | `长度/元素/元素文本/元素标签/键列表/字符串` 接受运行期才知道类型的值 |
| 类型标注 | `函数 f(列表: 列表, n: 整数) -> 字符串:`，标注优先于推断 |
| 所有权转移 | 变量间赋值、`追加`、列表字面量元素 |

## 当前进度（2026-09）

`bootstrap/lc.light`（约 1340 行，单文件，Light 写成）已经能：

- **词法**：缩进（增/减记号）、行尾记号、标识符/整数/浮点/字符串/算符/注释；
- **语法**：递归下降，覆盖函数（带参数与返回类型标注）、`让`/`设`、`如果`/`否则如果`/`否则`、
  `当`、`返回`、`跳出`/`续`、`打印`、列表字面量、下标、方法调用（`.切片`）；
- **代码生成**：输出 LLVM IR —— 表达式（整字/串字/变量/单双元/列表/下标/调用/短路/比较）、
  语句（声明/赋值/打印/追加/弹出/分支/循环/返回）、函数定义与调用、字符串常量表、
  运行时声明；**每个基本块都补终结指令**（`闭块`），保证 IR 合法；
- **调试模式**：输入以 `#tokens` 开头只打印记号；以 `#dump` 开头只打印语法树。

已验证（自举编译器生成 IR → clang 链接 `libnlightrt.a` → 运行）：

```

函数 求和(数字们: 列表) -> 整数: ...     # 列表遍历 ✓
当/如果/否则如果/跳出                     # 控制流 ✓
打印("列表求和: ", 求和(数们))            # 格式化输出 ✓
```

## 自举成立（stage2 == stage3）

`scripts/bootstrap.sh` 一次跑完 stage1/2/3 并比较产物。当前结果：

```
=== 2/5 lc1 编译 lc.light，产出 stage2.ll
stage2.ll 24096 行
=== 4/5 stage2 编译 lc.light，产出 stage3.ll
stage3.ll 24096 行
=== 5/5 定点比较 stage2.ll 与 stage3.ll
*** 自举成立：stage2.ll == stage3.ll ***
自举 OK
```

即：用 Light 写的编译器（`bootstrap/lc.light`）编译自身，得到的编译器
生成的 LLVM IR 与上一代逐字节一致——自举定点成立，`nlightc` 的核心已能用
Light 自我维护。

打通过程中补齐的语言能力（`nlightc` 与自举编译器同步实现）：

| 能力 | 说明 |
| --- | --- |
| 短路 `且`/`或` | 结果槽提升到入口块，跨基本块满足支配关系 |
| 动态值 | 列表下标读返回带运行期标签的值；`light_tagged/untag/tag_of` |
| 动态内建 | `dynamic_get/len/to_text/contains` |
| 所有权 | 变量间赋值、`追加`、列表字面量转移所有权，区分借用值 |
| 字符串按值传参 | `light_str_dup`，容器仍按引用借用 |
| 类型标注 | `函数 f(a: 整数) -> 字符串:` |
| `合并` 接受未知类型 | 动态数组也能拼字符串（`light_str_join`） |
| 参数个数检查 | nlightc 与自举编译器都会在实参/形参个数不符时报错 |

自举编译器沉淀的 LLVM 规则：

- `闭块`/`开块`/`记跳转`：终结标记 + 前驱列表，避免空基本块与 phi 前驱不匹配；
- 所有 `alloca`（含短路结果槽、语句变量槽）都提升到入口块；
- 输出代码用 `合并` 一次成型：逐行字符串相加是 O(n²)，24000 行会卡死。

### 尚未完成

1. 代码生成只覆盖子集：浮点只支持字面量与打印；不支持元组、字典字面量、
   `对于`、多文件、页面元素、FFI、REPL。
2. 与 Rust 版 `nlightc` 的行为差异：`打印(非字面量, 参数...)` 参考实现按元组输出
   （`(a, x, 3)`），自举版只输出格式串本身。
3. `nlightc` 的页面元素、FFI、REPL 尚未移植到 Light。

## 子集补全后的状态

`scripts/corpus.sh`（stage1 与 stage2 差分回归）：**23 个示例一致 / 1 个超出子集 / 0 不一致**
`scripts/bootstrap.sh`：定点成立（stage2.ll == stage3.ll）

本阶段补进自举编译器的语法与内建：

- 语句：`断言`、`抛出`、`尝试/捕获/最终`、`线程`、`对于`、`汇编`、`外部`、`导入`、`从…导入`
- 表达式：元组字面量、`//` 整除、`**` 幂、字符串方法（`大写/小写/去空白/查找/替换/分割/包含/切片`）
- 内建：`范围`、`数组`、`字典`、`求和`、`最大`、`最小`、`绝对值`、三角/对数/取整、
  `排序`、`索引`、`查找`、`读取文件`、`写入文件`、`文件存在`、`环境变量`、`执行`、
  `布尔`、`浮点`、`命令行参数`、以及 8 个内存原语（`内存分配/释放/复制/置零/整数读写/字节读写`）
- 语义对齐：`/` 恒为浮点除法（整数整除用 `//`）、布尔打印用「真/假」、
  列表用方括号、元组用圆括号、用户函数优先于同名内建、无标注时推断返回类型
- 诊断：`错误输出` 写 stderr，编译产物不再被错误信息污染

顺带修掉的编译器缺陷（都是自举/对比测试逼出来的）：

1. 浮点字面量被发成 `fadd double 0.0, 0x3ff0...`——LLVM 里十六进制是整数，浮点数值全错
2. 列表字面量里的嵌套容器被 `set_copy_tag` 后立刻 free，访问时悬垂
3. `light_array_set_copy_tag` 对非字符串也要复制字符串——数组元素被当字符串 dup
4. 字符串变量之间赋值是「转移」，给目标重新赋值时会 free 掉源还在引用的内存
5. 函数调用实参个数不校验，少传会让被调函数读到未初始化槽
6. 自举编译器里 `打印 值` 把实参多包了一层列表，所有无括号打印都失败
