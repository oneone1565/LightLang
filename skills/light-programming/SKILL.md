# Light 编程规范

## 适用范围

使用本 Skill 编写、修改或审查 `.light` 源码。目标是保持中文语法简洁、行为可预测，并让程序能够通过 `nlightc` 或 `nlightGo` 构建。

## 项目约定

- 源码使用 `.light` 扩展名。
- 简单程序直接使用顶层语句，不为普通脚本强行添加 `main`。
- 需要 Cargo 依赖、FFI、Web 或 GUI 时，建立 `lightGo.toml`。
- 从项目任意子目录执行 `nlightGo 构建` 或 `nlightGo 运行`；工具会向上寻找 `lightGo.toml`。
- 目标程序默认使用 Release；只有开发调试时使用 `--debug`。

## 基础语法

```light
名字 = "LightLang"
数字 = 42
比例 = 1.5
开关 = 真
空值 = 空
打印 名字
```

- 变量可以写作 `名字 = 值`，不需要 `让`。
- 字符串使用单引号或双引号。
- 整数、浮点数、布尔值和空值是独立类型。
- 除法 `/` 产生浮点数；整除使用 `//`。
- 字符串相加表示拼接。

## 控制流

```light
如果 数字 > 0:
    打印 "正数"
否则如果 数字 < 0:
    打印 "负数"
否则:
    打印 "零"

当 数字 < 10:
    数字 = 数字 + 1

对于 项目 在 范围(5):
    打印 项目
```

- 条件必须产生真假值。
- 块使用冒号和缩进，不能混用 Tab 和空格。
- 循环内使用 `跳出` 和 `继续`。
- 优先使用 `对于 ... 在 ...` 遍历数组，避免手写索引循环。

## 函数

```light
函数 加一(值):
    返回 值 + 1

打印 加一(41)
```

- 函数名和参数名使用简短中文或英文标识符。
- 需要返回值时显式写 `返回`。
- 不要依赖隐式返回值。
- 函数参数和返回值目前主要使用整数、浮点数、布尔值、字符串句柄和运行时对象句柄。

## 容器

```light
列表 = [1, 2, 3]
元组 = (1, "二", 真)
字典 = {"名称": "Light", "数量": 2}
打印 列表
打印 元组
打印 字典
```

- 列表、元组、字典使用对应的格式化输出。
- 需要索引时使用 `值[下标]`。
- 列表元素赋值使用 `列表[下标] = 值`。
- 不要把复杂容器当整数打印或参与算术。

## 字符串

字符串可以使用函数式写法：

```light
文本 = " Hello LightLang "
打印 文本.去空白()
打印 文本.大写()
打印 文本.小写()
打印 文本.替换("Light", "World")
打印 文本.查找("Light")
打印 文本.分割(" ")
```

- 字符串方法接收字符串作为隐式接收者。
- 对可能不存在的输入先使用空值判断。
- 处理用户输入时优先 `输入()`，读取后及时判断空字符串。

## 打印格式化

`打印` 支持 Python 式占位符：

```light
名字 = "LightLang"
打印("你好，{名字}")
打印("下个版本 {1 + 1}", 0)
打印(f"f 前缀：{名字}")
打印("{} 与 {}", "甲", "乙")
```

- `{名字}` 取当前作用域变量，`{表达式}` 求值后插入。
- `{}` 按顺序填位置参数，`{0}`、`{1}` 按下标填；`{{`、`}}` 输出字面量花括号。
- 位置参数只在第一个参数是字符串字面量时生效：`打印(3, 4)` 打印元组 `(3, 4)`。
- 名字写错会在编译期报「未定义变量」。
- 同一写法适用于 `页面` 块与交互模式。

## 异常

```light
尝试:
    抛出 "发生错误"
捕获 错误:
    打印 "捕获：" + 错误
最终:
    打印 "清理完成"
```

- 断言只在 Debug 构建中启用。
- Release 构建会移除 `断言` 的条件检查。
- 不要用异常处理隐藏数据损坏或资源错误。

## 线程

```light
打印 "主线程开始"

线程(1):
    打印 "线程一"

线程(2):
    打印 "线程二"

打印 "主线程结束"
等待全部()
```

- 线程块适合互不依赖的任务。
- 线程之间共享复杂可变对象前，必须先设计同步策略。
- 主线程没有语句时不产生额外输出；程序结束前会自动等待线程。
- 当前线程函数应保持简单，优先通过参数传递普通数据。

## nlightWeb

网页语法必须在文件开头导入 `lightWeb`（不导入会报「请先在文件开头导入」）。
同一个程序可以同时提供后端接口和浏览器页面：

```light
导入 "lightWeb"

函数 接口(请求):
    返回 "后端接口"

路由("GET", "/api", 接口)

页面 (标题="hello" 图标=none):
    语言="zh-cn"
    主题="dark"
    CSS = "h1 { color: #ff6b35; }"
    打印 "<h1>hello</h1>"
```

- `路由` 返回普通文本时使用 `text/plain`。
- `页面` 返回浏览器可渲染的 HTML，并支持 `语言`、`主题`、`标题`、`图标` 和 `CSS`/`样式`。
- 页面内的 `打印` 内容写入 HTML 响应；后端函数中的 `打印` 仍输出到终端。
- 当前页面默认注册到 `/`，路由路径必须精确匹配。
- 启动和停止服务使用 `nlightGo web start` 与 `nlightGo web stop`，中文命令是 `nlightGo 网页 启动/停止`。

## 页面元素

`页面` 代码块内可直接写元素语句，不要手写 HTML：

```light
页面 (标题="demo" 图标=none):
    主题 = "dark"
    标题 "欢迎" 级别=1
    段落 "版本 {1 + 1}。"
    按钮 "提交" 动作="/submit" 方式=post 样式=主要
    输入框 名称="名字" 标签="名字" 占位提示="请输入"
    下拉框 名称="城市" 选项=["北京", "上海"] 选中="上海"
    表格 表头=["名称", "值"] 行=[["a", "1"]]
    容器 元素=form 动作="/submit" 方式=post:
        按钮 "发送"
    提示 "已保存" 级别=成功
```

- 可用元素：标题、段落、按钮、链接、图片、输入框、文本域、复选框、单选框、下拉框、列表、表格、分隔线、卡片、标签、进度条、代码块、提示、容器、结束。
- 属性值可写单词（`样式=主要`）；与变量同名时按变量取值。
- `容器` 用冒号加缩进块自动闭合，也可用 `结束` 手动闭合。
- 表单参数用 `请求参数(请求, "名字")` 读取；元素只能写在 `页面` 内。
- 需要自定义 HTML 时仍可使用 `打印 "<div>…</div>"`。

## 别名：用自己的写法

`.llang` 文件里每行写一条 `别名 : 原名`，导入后两种写法完全等价：

```
# 英文别名.llang
print : 打印
len : 长度
```

```light
导入 "英文别名.llang"
print "hi"     # 等价于 打印 "hi"
```

扩展名 `.llang` 不能省，否则分不清是 .light 模块、.rs 原生模块还是别名文件。
用户自己定义的同名函数优先于别名。别名只改名字，不改变类型与运行期表示。

## 断言

```light
断言 数量 >= 0, "数量不能为负数"
```

- 使用 `nlightc --debug` 或 `nlightGo 构建 --debug` 启用。
- 断言消息使用字符串字面量。
- 不要把业务逻辑依赖在 Release 断言上。

## 构建与验证

普通程序：

```bash
nlightc hello.light -o hello
./hello
```

临时运行单个文件：

```bash
nlight hello.light
```

交互模式（逐句执行，变量保留，只显示当前句输出）：

```bash
light
```

```text
>>> a = 1
>>> a = a + 1
>>> 打印 a
2
```

- 以 `:` 结尾的语句（函数、`如果`、`当`）按缩进跨行输入，缩进回退或空行时执行。
- 会话源码位于当前目录，`导入 "模块名"` 按当前目录解析。
- 失败的语句会被丢弃，可改正后重输；`保存 <文件>` 可把会话导出为 `.light` 源码。

项目程序：

```bash
nlightGo 构建
nlightGo 运行
nlightGo 清理
```

开发检查：

```bash
nlightGo 构建 --debug
cargo check --release
```

## 代码审查清单

- 是否使用了正确的 `.light` 扩展名和缩进？
- 是否避免了不必要的 `main`？
- 是否对 `输入()` 结果做空值处理？
- 是否区分了字符串、普通值、列表、元组和字典？
- 是否在 Release 依赖了断言行为？
- 线程任务是否互相独立并有明确等待？
- Web 页面是否返回 HTML，后端是否使用正确的响应类型？
- 是否用 `nlightGo 构建` 和实际运行验证过？
